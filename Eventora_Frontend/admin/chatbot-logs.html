Demonstration data — the AI module is not built. Every entry below is an invented sample used to construct this monitoring interface. No real user has ever interacted with an Eventora chatbot, no message here came from a person, and no AI service processed any of it. The chatbot is scheduled for a later development phase.

Read-only monitoring. chatbot_logs is a conversation history. Database v1.0 defines no operation that modifies it, so this page offers none — there is no delete, no bulk purge, no user ban and no model retraining control. Adding any of those would imply backend capability that does not exist.

What is stored, and what is not. chatbot_logs holds id, user_id, session_id, sender_type, message_text and created_at — that is all. Intent, response time, model name and safety flags have no column in Database v1.0 and are shown here as demo-only fields to illustrate what monitoring would look like. No column has been invented to support them.
