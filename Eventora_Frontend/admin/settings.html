Two-factor authentication

Not implemented

Demo-only — not persisted in Database v1.0

Two-factor authentication is not implemented and has no column in Database v1.0. No toggle is offered here, because a switch that cannot be honoured would imply the account is protected when it is not.

Active sessions

Not modelled

Demo-only — not persisted in Database v1.0

Database v1.0 does not model sessions, so no session history is shown. Displaying a device list would be fabricated. When authentication is built, signing out everywhere will simply invalidate the PHP session.

Commission configuration

The current model and why the rate is not editable here

Demo-only — not persisted in Database v1.0
Current configured rate 10.00%
Commission records 33
Commission recorded to date Rs. 349,600
Why this rate is displayed, not edited. vendor_profiles.commission_rate exists per vendor with a default of 10.00%, but there is no platform-level default column in Database v1.0. More importantly, changing a rate must never alter existing records: commissions.commission_percentage is snapshotted at booking time, so a booking taken at 10% keeps 10% permanently. A rate editor here would need a clear rule for which future bookings it affects, and that rule is not yet approved.

The 10% figure shown is the current configured demo value used throughout the project. It has not been changed, and it cannot be changed from this page.

Danger zone

Operations that are deliberately not offered

No destructive platform operations

There is no "reset platform", "purge bookings", "delete all logs" or "wipe demo data" control here, and there will not be one. Bookings, payments, commissions and reviews hold foreign keys with ON DELETE RESTRICT, so the database itself refuses those deletions. Accounts are blocked, never deleted; categories are deactivated, never removed. Offering a destructive button that the schema would reject would be misleading.
